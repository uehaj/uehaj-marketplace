# ツリービューの表示

要求・要件の全体構造を種別カラム（BR / SR / SOL / MO）で見るツリービューを開く。
生成の実態は `scripts/req_tree.ts`（レビューサーバ経由）または `scripts/req_bundle.ts`
（`req gen`。未稼働時の静的生成、バンドル内の tree ペインとして束ねられる）。

## 実行手順

1. **レビューサーバが稼働していればそれを開く**（既定ポート 8765 固定）。
   稼働中のビューはリクエストごとに正本から再生成され、レビュー操作（書き戻し）も
   有効なので、静的生成より常にこちらを優先する。

   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8765/ || true
   ```

   200 が返れば:

   ```bash
   open http://127.0.0.1:8765/
   ```

   `#レコードID`（例 `http://127.0.0.1:8765/#SR-34`）で特定レコードのモーダルを
   直接開ける。開いたことを伝えて終了。
   （スクリプト自体を修正した直後は再起動が必要——判断手順は req-review スキルの
   手順 1 を参照。）

2. **未稼働なら `req gen` でバンドルを生成して開く**（読み取り専用。レビュー操作は無効）。
   個別ビューの HTML はもう生成しない。バンドル内でツリーを見る（切替は上部ナビ、または
   `#tree` を付けて開けば起動時からツリーペインが選ばれる）。

   - プラグインとしてインストールされている場合:

     ```bash
     node "${CLAUDE_PLUGIN_ROOT}/scripts/req_bundle.ts" \
       --root "${CLAUDE_PROJECT_DIR}/docs/requirements" \
       --out "${CLAUDE_PROJECT_DIR}/docs/generated/バンドル.html"
     open "${CLAUDE_PROJECT_DIR}/docs/generated/バンドル.html#tree"
     ```

   - このリポジトリ自身（セルフホスティング先）では:

     ```bash
     node bin/req.ts gen && open "docs/generated/バンドル.html#tree"
     ```

   `open` はプラットフォーム依存。開けなければパスを案内するだけでよい。

3. **一言そえる**: どちらで開いたか（サーバ配信＝レビュー可／静的＝読み取り専用）、
   カラムの折りたたみ・「要レビューのみ」絞り込み・カードクリックで詳細モーダル＋
   トレースハイライトが使えること。レビューをしたい流れなら req-review スキルへ
   （サーバを立てて書き戻し可能にする）。
